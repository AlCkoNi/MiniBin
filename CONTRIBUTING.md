# Contributing

1. Создайте отдельную ветку от `main`.
2. Не добавляйте в исходники персональные абсолютные пути, имена пользователей, диски или секреты.
3. Новые пользовательские настройки должны иметь безопасное значение по умолчанию.
4. Опасные операции удаления должны быть явно описаны в README/документации и не должны включаться автоматически без необходимости.
5. После изменения функционала обновите `src/version.go`, `CHANGELOG.md` и соответствующую документацию.
6. Соберите релиз через `scripts/build_release.ps1` и проверьте SHA-256.
7. Для pull request опишите назначение изменения, пользовательское поведение и способ проверки.
