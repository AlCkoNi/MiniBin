# My Function — точка расширения MiniBin

## Назначение

`My Function` — специально зарезервированное подменю для дополнительных функций, которые разработчик или пользователь хочет добавить поверх базовых возможностей MiniBin.

В публичной версии MiniBin 1.1 подменю **намеренно пустое**. В нём нет скрытых действий, персональных путей, синхронизации папок, удаления пользовательских каталогов или другой логики, завязанной на конкретный компьютер.

Главная идея: базовое меню MiniBin остаётся стабильным, а все дополнительные возможности добавляются в одном предсказуемом месте.

## Что рекомендуется размещать внутри

Примеры подходящих расширений:

- синхронизация выбранных пользователем папок;
- очистка дополнительных каталогов;
- запуск пользовательского скрипта или команды;
- резервное копирование;
- очистка кэша конкретного приложения;
- включаемая дополнительная операция, выполняемая вместе с `Empty`/`Auto Clean`;
- сервисные действия разработчика.

Не рекомендуется добавлять в публичную сборку функции с жёстко заданными именами пользователей, буквами дисков, секретами, токенами или абсолютными путями конкретного компьютера.

## Где это находится в коде

Подменю создаётся в `src/main.go`:

```go
appState.myMenu = createPopupMenu()
appendMenu(appState.menu, mfPopup, appState.myMenu, "My Function")
```

В версии 1.1 между этими строками намеренно нет `appendMenu(appState.myMenu, ...)`, поэтому подменю пустое.

## Пример: добавить обычную команду

### 1. Добавьте ID

В `src/win32.go`:

```go
const (
    // существующие ID...
    idMyAction
)
```

ID должен быть уникальным.

### 2. Добавьте пункт в `My Function`

В `buildMenus()` файла `src/main.go`:

```go
appendMenu(appState.myMenu, mfString, uintptr(idMyAction), "My Action")
```

### 3. Добавьте обработчик

В `handleCommand()`:

```go
case idMyAction:
    runMyAction()
```

### 4. Вынесите реализацию в отдельный файл

Например:

```text
src/feature_myaction.go
```

Это упрощает сопровождение и не перегружает `main.go`.

## Пример: переключатель с галочкой

Если функция должна включаться/выключаться:

1. добавьте boolean-параметр в `Config`;
2. реализуйте чтение/запись параметра в `src/config.go`;
3. добавьте command ID и пункт меню;
4. при выборе переключайте значение;
5. вызывайте `checkMenuItem(appState.myMenu, idMyAction, enabled)`;
6. сохраняйте конфигурацию после изменения.

Опасные или удаляющие данные функции должны быть **выключены по умолчанию**.

## Выполнение вместе с очисткой

Если расширение должно выполняться после очистки Корзины, добавляйте его в фоновую часть `startCleanup()`:

```go
go func() {
    emptyRecycleBin(appState.hwnd)
    clearTemporaryFiles()

    if appState.config.MyActionEnabled {
        runMyAction()
    }

    postMessage(appState.hwnd, wmCleanDone)
}()
```

Не выполняйте длительные файловые операции непосредственно в `windowProc`, иначе меню системного трея может зависать.

## Правила для расширений

- Не храните пароли, токены и секреты в исходниках.
- Не используйте персональные абсолютные пути в публичной версии.
- Для путей используйте настройки, `os.UserHomeDir()`, `%USERPROFILE%`, `%LOCALAPPDATA%` и другие системные механизмы.
- Перед рекурсивным удалением проверяйте границы целевого каталога.
- Учитывайте junction/reparse point/symlink.
- Документируйте, какие данные читаются, копируются или удаляются.
- Тяжёлую работу выполняйте в goroutine.
- После добавления функции увеличивайте версию и обновляйте `CHANGELOG.md`.

## Смысл пустого My Function в публичной сборке

`My Function` — это не незавершённая функция. Это стабильная точка расширения проекта. Публичная базовая сборка остаётся универсальной, а разработчик может добавлять туда собственные функции без перестройки верхнего уровня меню.
